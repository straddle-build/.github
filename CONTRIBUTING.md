# Contributing

We welcome focused issues and pull requests.

1. Fork the repository or create a short-lived branch if you have write access.
2. Make one coherent change and add or update tests when behavior changes.
3. Run the repository's documented validation locally.
4. Open a pull request that explains the behavior change and the evidence that proves it.

All required checks must pass and review conversations must be resolved before merge. Maintainer reviews may be requested through CODEOWNERS, but approval is not a mandatory merge gate.

For vulnerabilities, follow the [security policy](SECURITY.md) instead of opening a public issue.
